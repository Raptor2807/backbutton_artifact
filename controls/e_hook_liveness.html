Control E: does the Location.replace hook actually fire?

Every other control destroys the document that called location.replace(), so window.__bbh.location_replace_count is unreadable afterwards. This page calls replace with a fragment, which does not create a new document — so __bbh survives and the counter can be read.

Expected: location_replace_count == 1.

Why it matters beyond this harness: location_redirect_after_back is one of the five rules that short-circuit classify_page() straight to HIJACKING. It depends on this hook. If the counter reads 0 here, that rule has never fired in production and is dead code — which changes what the five shortcut rules actually did to the corpus.
